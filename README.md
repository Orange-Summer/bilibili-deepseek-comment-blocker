# 屏蔽 B站 DeepSeek AI 评论

交付脚本：同目录 `bilibili-deepseek-comment-blocker.user.js`，版本 0.2.1。

## 识别边界

当前按 UID 与文本规则过滤，不提供底层模型是否为 DeepSeek 的归因。

需要区分三个问题：账号是否是已知机器人、正文是否像生成文本、评论是否通过 Agent 提交。三者并不等价。真人可能粘贴模型输出，Agent 也可能发送真人写好的句子。

本脚本没有获得能够证明提交方式的服务端凭据，也没有经过真实样本集的准确率评估。因此“规则命中”只表示满足用户的过滤偏好，不能据此认定作者使用了 Agent。未经测试，不能承诺能过滤所有此类评论。

## 具体规则

优先级：暂停 → UID 黑名单 / 自定义正文片段 → 组合规则。

| 依据 | 默认行为 | 解释 |
|---|---|---|
| 用户添加的 UID 黑名单 | 评论响应中移除 | 只按作者 UID；已加载或未拦截的评论仍用页面折叠兜底 |
| 自定义正文片段 | 折叠 | 纯字面包含匹配；忽略大小写、做 Unicode 规范化 |
| 昵称以“大肥鱼/大肥鲸/鲸鱼娘”结尾 | 加 3 分 | 单独命中只标记；同名、模仿仍可能误伤 |
| 正文出现“本鱼/本鲸/本肥鱼” | 加 2 分 | 单独命中只标记；也可能是引用 |
| 正文开头符合 AI 自我介绍模板 | 加 3 分 | 单独命中只标记；并非通用 AI 检测器 |
| 单字“鱼/鲸”、普通 @、冒号、破折号、长段落 | 不计分 | 避免以常见表达直接屏蔽 |

这里的分数是人为设置的规则权重，不是“AI 概率”。昵称与自称也不是相互独立的统计证据。默认黑名单和屏蔽词为空，不附带未经核实的账号清单。

三种模式：

- `observe`：响应层不删除；所有页面命中只标记，包括黑名单。
- `balanced`：默认。黑名单在响应层移除；自定义片段或累计分数 ≥ 5 在页面折叠，其余 ≥ 2 分只标记。
- `strict`：黑名单仍在响应层移除；自定义片段或累计分数 ≥ 2 在页面折叠，误伤更多。

正文判定前会尝试去掉开头的“回复 @某人:”前缀，减少被回复者昵称对判断的影响。用户主动引用、截图文字、变体自称仍无法完整区分。

## 两层处理

- **响应层**：在 `document-start` 尝试为页面的 Fetch 和 XMLHttpRequest 安装钩子，仅匹配 `api.bilibili.com` 的四个 GET 评论列表接口：`/x/v2/reply`、`/x/v2/reply/main`、`/x/v2/reply/wbi/main`、`/x/v2/reply/reply`。按 `member.mid` 过滤用户指定的 UID 黑名单。文本和昵称规则不参与响应过滤。
- **页面层**：继续对剩余评论使用原有文本规则折叠；也处理加入黑名单前已渲染的评论，以及响应层未能处理的评论。

响应过滤覆盖主评论、楼中楼预览/分页和受支持格式的置顶评论。黑名单主评论被移除后，其下整楼回复也不显示；正常主楼下只移除黑名单子回复。

服务器的游标、分页总数和回复总数保持原值，避免用局部预览数量改坏翻页。这意味着显示的总数可能多于实际可见条数，也可能出现空白的一页或空回复列表。脚本不自动补抓下一页。

**从响应中移除的内容没有页面占位，无法点击展开。** 移出黑名单、暂停或切到观察模式后，需要刷新页面重新取得这些内容；页面中仅被折叠的评论仍可立即展开。

只在响应格式可识别且成功处理时替换响应；业务错误、HTTP 错误、JSON 解析失败和不支持的响应类型沿用原响应。它不阻止请求发出，不减少服务器返回的数据量，也不修改服务端评论。初始内嵌数据、注入前已经发起的请求、页面提前缓存的原始请求函数，以及其他插件覆盖钩子的情况，仍依赖页面折叠兜底，不能保证所有黑名单评论绝不闪现。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 打开管理面板，新建脚本，删除示例代码，把 `bilibili-deepseek-comment-blocker.user.js` 的完整内容粘贴进去，保存。
3. 刷新 B 站视频页，滚动到评论区。
4. 点浏览器工具栏 Tampermonkey 图标，在脚本菜单选择“当前扫描状态”。

如果脚本管理器提示需要浏览器“允许运行用户脚本”，按其提示启用。菜单和本地存储使用 Tampermonkey 的 [官方 GM API](https://www.tampermonkey.net/documentation.php)。

脚本不额外发起网络请求，不上传评论、不调用模型、不发送评论，也不修改 B 站账号黑名单。设置仍保存在 Tampermonkey 本地的 `agent-filter-v1` 中；本次升级保留脚本名称、namespace 和存储键。响应过滤和页面折叠都只影响本浏览器。

## 使用

本版已移除 UID 白名单；升级时自动丢弃旧设置或导入备份中的 `allowedUIDs`，原有黑名单和文本规则继续保留。

从旧名称脚本升级时，先通过“设置 / 导入导出 JSON”备份名单，再覆盖原脚本；如新建了独立脚本，需导入备份并停用旧脚本。

- 评论旁的“屏蔽此 UID”：将作者加入本脚本黑名单；已有评论页面折叠，后续受支持的评论响应直接移除。
- “展开原文”：当前页面临时展开；修改规则后重新判定。
- “移出黑名单”：撤销该 UID 的屏蔽。如果仍命中组合规则，可能继续折叠。响应中已移除的评论需刷新恢复；也可从 JSON 设置中删除 UID。
- 菜单“暂停 / 恢复”：停止后续响应过滤，并恢复页面层折叠；响应中已移除的评论需刷新恢复。再次点击继续过滤。
- 菜单“设置 / 导入导出 JSON”：复制当前设置可备份；粘贴设置并确认可导入。

例如，下面的 UID 仅用于展示格式，请替换成自己核实的账号 UID：

```json
{
  "enabled": true,
  "mode": "balanced",
  "blockedUIDs": ["123456789"],
  "blockedPhrases": [],
  "personaRules": true
}
```

UID 必须使用带引号的十进制字符串，防止 JavaScript 数值精度丢失。可以从作者主页 `https://space.bilibili.com/数字UID` 确认。昵称不是稳定标识；改名后，UID 规则仍然有效。

若希望只按明确账号名单过滤，把 `personaRules` 改成 `false`。若暂时只想评估误伤，把 `mode` 改成 `observe`。

## 适配与性能

目标为 PC 网页的视频页和番剧播放页。响应层要求使用上述接口和受支持的数据结构；页面层适配开放 Shadow DOM 中的 `bili-comment-renderer`、`bili-comment-reply-renderer`。不覆盖动态、空间、手机客户端或弹幕；旧版非组件评论区不支持页面兜底。

脚本进入开放 shadow root，分别读取每条正文和作者区域；不会把整楼文本当作主评论，也不会把正文 @ 对象的主页链接当作作者 UID。页面层折叠主评论 renderer 时，位于 thread 中的回复列表保持原有结构；正常主楼里的命中子回复单独折叠。响应层移除主评论则会带走整楼，见“两层处理”。它不自动展开、请求或扫描未加载的评论。

组件内部变化使用 MutationObserver，并合并短时间内的更新。每 2.5 秒执行一次兜底扫描，以发现延迟创建的 shadow root、组件重建及页面路由变化；后台标签暂停该轮询。它仍会遍历已加载评论，超长列表的实际开销需要实站评估。切勿把它描述为零开销。

设置修改只即时作用于当前标签；其他已打开标签请刷新。页面组件改版、关闭 shadow root 或其他评论区插件改动结构时，需要更新适配。如果页面层作者 UID 读取失败，该条的 UID 按钮与折叠兜底不可用，但已安装的响应钩子仍可按接口中的 UID 过滤；能读到正文时仍可运行文本规则。“扫描 0 条”表示没有读取到目标评论，不表示页面没有 Agent 评论。

不建议与另一个会从接口删除评论的脚本同时评估：已经被另一个脚本删掉的内容，这个脚本无法恢复。

## 验证情况与后续改进

已通过 Node.js 语法检查，以及 Edge 无头浏览器中 19 项页面折叠检查和 31 项响应层测试。页面测试覆盖原有规则与恢复行为；响应测试使用本地路由夹具，覆盖 Fetch、Request/URL 输入、克隆响应、XHR 文本/JSON/二进制类型、复用请求实例、黑名单、置顶与子回复、异常响应和无关请求放行。

这些测试使用本地构造页面，不是登录 B 站后的真实页面测试，也未验证实际 Tampermonkey 注入环境。上线使用前请先在自己常看的视频中观察误伤与漏检。

如需进一步提高覆盖率，优先收集去标识化的误判/漏判样本，再调整特征。可以建立用户核实的 UID 清单，记录来源、核实日期和撤销记录；不要把疑似昵称自动永久加入黑名单。

重复内容、发评间隔、跨视频复用可以作为后续弱信号，但单个已加载页面无法给出完整行为历史。本版没有实现跨页采集、近似重复检测或行为分析。也没有接入外部 AI 检测服务。

若后续确认评论接口提供与 Agent 身份相关的公开字段，可以逐项验证后增加辅助识别。当前响应层只根据用户指定的 UID 名单过滤，不凭未知字段名称猜测身份。

## 本地开发

安装 Node.js 20 或更高版本后，在仓库目录运行：

```bash
npm install
npx playwright install chromium
npm run check
npm test
```

测试默认使用 Playwright Chromium。如使用本机 Edge，可设置 `BROWSER_CHANNEL=msedge npm test`。测试只创建本地模拟页面，不访问 B 站或读取登录账号。

仓库只保存脚本、文档和测试，不包含浏览器中已保存的 UID 名单。迁移源码不改变 Tampermonkey 内现有脚本的存储。
